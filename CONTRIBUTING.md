# Как вносить правки

Журнал готовится к реальной печати и заполнению ручкой. Ошибка вёрстки
стоит дорого: после типографии её не исправить. Поэтому правила ниже
жёстче обычных.

## Перед началом

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
./build.sh
```

`build.sh` собирает книгу и прогоняет проверку. Если он не отработал на
чистом дереве — чините окружение, а не вёрстку.

## Что можно править и где

| хочу изменить | файл |
|---|---|
| текст справочной страницы | `src/reference.py`, функция `p_<имя>` |
| порядок или состав страниц | список `pages` в `src/reference.py` |
| векторную схему | `src/figures.py` |
| поля, перфорацию, палитру, карточку записи | начало `src/logbook.py` |
| проверки готового PDF | `src/check_margins.py` |

## Инварианты

Нарушать нельзя — каждый оплачен ошибкой, дошедшей до готового PDF.

1. **Отступы задаются константами** `GAP_TEXT`, `GAP_LIST`, `GAP_TABLE`,
   `GAP_FIG`, `GAP_NOTE`. Один тип элемента — один отступ во всей книге.
   Подгонка интервала под конкретную страницу запрещена.
2. **Не помещается — режьте содержимое, а не интервал.** По убыванию
   предпочтительности: сократить текст, уменьшить высоту картинки,
   разделить страницу надвое. Кегль основного текста не уменьшать.
3. **Монохром.** Только оттенки чёрного. Цвет при печати в одну краску
   станет серым пятном.
4. **Номера страниц не печатаются.** Листы съёмные, порядок задаёт
   владелец. `folio()` намеренно пустая.
5. **Подписи двуязычные.** `field(c, x, y, w, "русский", "english")`.
6. **Фактология проверяется.** Числовые ориентиры зависят от обучения,
   снаряжения, местных правил и плана — где существенно, нужна оговорка.
   Не выдумывать значения, не подавать условное как универсальное правило.
7. **Тон профессиональный.** Коротко, без назидательности и эмоциональных
   усилений. Терминологию не упрощать до бытовой.
8. **Не трогать страницы, которых задача не касается.** Стилистические
   улучшения по своей инициативе не вносить.
9. **Карточка записи занимает разворот** и начинается с чётной страницы.
   В сборке есть проверка чётности — не ломайте её.

## Формат заявки на правку текста

Ищите по цитате, а не по номеру страницы: номера смещаются при любом
изменении объёма.

```
Файл: src/reference.py, функция p_<имя>
Сейчас: «<точная цитата>»
Заменить на: «<новый текст>»
Причина: <почему>
Приоритет: CRITICAL | SHOULD | OPTIONAL
```

## Иллюстрации

1. Задание составляется по `docs/illustration-brief-template.md`.
2. Файл: монохром, белый фон, без текста в кадре, от 2048 px по длинной
   стороне.
3. `python3 tools/prepare_illustrations.py <папка> <mapping.txt>`.
4. Вставить блоком `("img", ("имя", высота_мм, "подпись"))`.

Всё, где важна геометрическая точность — углы секторов огней, формы
навигационных знаков, пропорции графиков, ход верёвки в узле — рисуется
вектором в `figures.py`, а не генератором изображений.

## Как правка попадает в main

Ветка `main` защищена: прямой push в неё отбивается, force-push и удаление
запрещены, история линейная. Порядок один для всех, включая владельца
репозитория.

```bash
git switch -c fix/<коротко-о-чём>
# правите, собираете, смотрите глазами
./build.sh
git push -u origin fix/<коротко-о-чём>
gh pr create --fill
```

Дальше CI сам собирает книгу и гоняет `check_margins.py`. Пока проверка
«собрать книгу и проверить вёрстку» не позеленела, кнопка merge не
работает — съехавшая вёрстка в `main` не попадёт. Апрув не требуется:
мержите сами, когда сборка прошла. Удобно включить auto-merge и не ждать:

```bash
gh pr merge --squash --auto
```

Мерж только squash или rebase, ветка удаляется автоматически. Обсуждения
в PR нужно закрыть до мержа.

Теги релизов `v*` неизменяемы: их нельзя ни удалить, ни переставить на
другой коммит. Это не формальность — по тегу CI собирает PDF, который
люди скачивают; переставленный тег означал бы, что по той же ссылке
лежит другая книга. Ошиблись в релизе — выпускайте следующий.

## Перед тем как открыть pull request

- [ ] `./build.sh` отработал без ошибок;
- [ ] `check_margins.py` не нашёл выхода за поля и наложений;
- [ ] изменённые страницы отрендерены и просмотрены глазами;
- [ ] число страниц изменилось только если это было целью;
- [ ] в описании PR сказано, что не удалось сделать и почему.

Собранные PDF в репозиторий не коммитятся: `dist/` в `.gitignore`,
готовые файлы публикуются в релизах.
